# Windows authentication investigation

**Исследование событий аутентификации Windows в Wazuh**

Лабораторный проект для портфолио аналитика SOC.

**Период выполнения:** октябрь 2026 года.

## Цель

Проанализировать неуспешные и успешные сетевые входы Windows, сопоставить события по учётной записи, источнику, компьютеру назначения и времени. Определить, какие наблюдения требуют расследования и какие дополнительные данные помогут отличить атаку от ошибки пользователя или программы.

## Лабораторное окружение

| Компонент | Роль |
|---|---|
| Хост Windows 11, адрес `192.168.56.1` | Источник тестовых подключений; доступ к Wazuh Dashboard |
| Виртуальная машина Windows 11, `DESKTOP-KN3U7PI`, адрес `192.168.56.102` | Компьютер назначения; источник исследуемых событий Windows |
| Виртуальная машина Ubuntu Server с Wazuh | Сбор и просмотр событий |

Подключения выполнялись к общему ресурсу `SOC-Lab` по SMB. Использовались локальные учётные записи `bob`, `alice` и `svcbackup`.

Все попытки входа создавались намеренно в собственной лаборатории.

## Исследуемые события

| Событие Windows Security | Значение в расследовании |
|---|---|
| [4624](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4624) | Успешный вход |
| [4625](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4625) | Неуспешная попытка входа |
| [4740](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/auditing/event-4740) | Блокировка учётной записи |

Для сетевых входов проверялось поле `logonType` со значением `3`. При анализе отказов проверялись поля `status` и `subStatus`.

## Сценарии и результаты

| Сценарий | Наблюдаемые события | Интерпретация |
|---|---|---|
| Ошибка пароля для `bob`, затем успешный вход | 4625 → 4624 с интервалом около 29 секунд; одна учётная запись, источник и компьютер назначения | Последовательность совместима с исправлением ошибочного пароля. В реальном расследовании сама по себе не доказывает отсутствие атаки |
| Серия неверных паролей для `alice` | Шесть событий 4625 примерно за три минуты, событие 4740 и более позднее событие 4624 | Зафиксирована блокировка после серии отказов и последующий успешный вход. Причину серии в реальном инциденте нужно устанавливать по дополнительным данным |
| Регулярные ошибки входа для `svcbackup` | Шесть событий 4625 с интервалами примерно 113 секунд | В лаборатории попытки создавал скрипт PowerShell. В реальном инциденте регулярность поддерживала бы гипотезу автоматизации, но не доказывала бы использование сохранённого устаревшего пароля |

## Метод анализа

1. Выбирал временной диапазон и искал события нужной учётной записи в Wazuh.
2. Сопоставлял имя учётной записи, адрес источника и компьютер назначения.
3. Проверял тип входа и коды отказа.
4. Выстраивал события в последовательность от ранних к поздним.
5. Подсчитывал отказы и сравнивал интервалы между событиями.
6. Отделял подтверждённые наблюдения от возможных объяснений и определял следующие проверки.

Основные поля Wazuh: `data.win.system.eventID`, `data.win.system.computer`, `data.win.eventdata.targetUserName`, `data.win.eventdata.ipAddress`, `data.win.eventdata.logonType`, `data.win.eventdata.status`, `data.win.eventdata.subStatus`.

## Выводы и ограничения

- Серия отказов и блокировка заслуживают проверки, но сами по себе не устанавливают злонамеренность действий.
- Возможные объяснения для реального инцидента: подбор пароля, ошибки пользователя или автоматическое повторение подключений с неверными учётными данными.
- Для `svcbackup` исследовался учебный скрипт. Реальная служба или приложение с сохранённым устаревшим паролем в этом эксперименте не проверялись.
- Более поздний успешный вход подтверждает возможность входа в этот момент, но не устанавливает точную длительность предшествующей блокировки.
- В исходном рабочем журнале отсутствует подтверждение фактических настроек блокировки на момент каждого эксперимента.
- Сопоставление отказов с процессом на компьютере-источнике в этом разборе не выполнено.

## Дополнительные проверки

Для установления причины подобной последовательности в реальном расследовании потребовалось бы:

- Выявить процесс, создающий подключения на компьютере-источнике.
- Сопоставить отказы с запуском служб, заданий планировщика и приложений.
- Проверить, откуда программа получает учётные данные.
- Уточнить действия пользователя и сравнить их со временем событий.
- Зафиксировать политику блокировки и часовой пояс событий.
